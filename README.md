# redmine-custom-decrement-field

Redmine 6+ плагин: кастомное поле-счётчик, значение которого можно только
уменьшать кнопкой на карточке задачи. История списаний и их откат — через
обычные комментарии к задаче, без отдельной таблицы декрементов.

**Статус: скетч.** Это рабочий пример, собранный по мотивам обсуждения
архитектуры, а не готовый к продакшену плагин. См. «Известные ограничения»
внизу перед реальным использованием.

## Идея

- Поле — самое обычное кастомное поле Redmine (`int`), без регистрации
  своего `field_format`. Если плагин отключить, поле просто становится
  обычным целочисленным полем с последним посчитанным значением — ничего
  не ломается.
- Значение поля **всегда производное**: оно равно сумме чисел из всех
  комментариев к задаче, помеченных ключевым словом (токеном), включая
  самую первую запись — «сколько получили изначально». Отдельного поля
  под «исходное количество» нет: число, вписанное в поле при создании
  задачи, автоматически превращается в первый такой комментарий
  (`IssuePatch#custom_decrement_field_seed`), и дальше поле никогда не
  принимает прямой ввод — любая попытка отредактировать его руками
  перезаписывается при следующем же пересчёте
  (`IssuePatch#custom_decrement_field_recalculate`).
- Конфигурация (токен и опциональный статус, в который переводится задача
  при обнулении счётчика) хранится не в отдельной таблице плагина, а прямо
  в `description` самого кастомного поля — см.
  `lib/custom_decrement_field/token_config.rb`. Страница настроек плагина
  ничего не сохраняет, а просто помогает собрать эту строку.
- Права на списание не заводятся отдельным permission — используется
  штатное право Redmine `add_issue_notes`. Откат ошибочного списания —
  штатное удаление/правка комментария; пересчёт срабатывает автоматически
  через `JournalPatch`.
- При достижении нуля (или ухода в минус — это может произойти только в
  обход кнопки, через прямую правку комментария) кнопка декремента
  перестаёт быть доступна. Отрицательное значение не прячется, а
  показывается как есть — это сигнал, что история была подправлена в
  обход штатного пути.

## Установка

1. Склонировать в `plugins/redmine_custom_decrement_field` внутри
   установки Redmine.
2. `bundle install`, перезапустить Redmine (миграций нет — плагин не
   заводит собственных таблиц).
3. Создать обычное целочисленное кастомное поле для задач
   (Administration → Custom fields → New custom field → Issue, формат
   Integer), привязать к нужному трекеру.
4. Зайти в Administration → Plugins → Custom Decrement Field → Configure,
   собрать строку-маркер (токен + опционально статус при обнулении) и
   вставить её в конец description созданного поля.
5. По желанию — сделать поле read-only через Workflow для всех статусов,
   кроме начального: это только косметика, реальную защиту от порчи даёт
   код (см. ограничения ниже).

## Структура

- `lib/custom_decrement_field/token_config.rb` — парсинг/сборка маркера
  конфигурации в description поля.
- `lib/custom_decrement_field/stock_calculator.rb` — вычисление текущего
  значения по истории комментариев.
- `lib/custom_decrement_field/issue_patch.rb` — сид при создании задачи,
  пересчёт и переход статуса при каждом сохранении.
- `lib/custom_decrement_field/journal_patch.rb` — пересчёт при
  создании/правке/удалении комментария.
- `app/controllers/custom_decrement_field_controller.rb` — эндпоинт
  декремента (всегда −1, с блокировкой на нуле).
- `assets/javascripts/custom_decrement_field.js` + `lib/.../hooks.rb` —
  кнопка «−1», дорисовывается JS-ом поверх штатной вёрстки кастомного
  поля, без патчинга рендер-партиалов ядра.

## Известные ограничения / TODO

- Не проверено на реальном Redmine 6.x — точные названия хуков
  (`view_layouts_base_body_bottom`), CSS-класс строки кастомного поля
  (`cf_<id>`) и permission-чекбоксы удаления заметок стоит сверить с
  конкретной версией.
- Нет тестов.
- Величина декремента жёстко зашита как 1 (`DECREMENT_AMOUNT` в
  контроллере) — согласно обсуждению, произвольные значения допускаются
  только через ручную правку текста комментария, сознательно не вынесены
  в интерфейс.
- QR-сканер сознательно не включён в этот плагин — обсуждался как
  отдельный, независимый плагин с иным контрактом (см. историю
  обсуждения), сюда не добавлялся.
- Страница настроек не сохраняет состояние — это чистый JS-калькулятор
  строки маркера, что и задумано, но выглядит непривычно для типовой
  Settings-страницы Redmine.
