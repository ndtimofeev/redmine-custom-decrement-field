# redmine-custom-decrement-field

Redmine 6+ плагин: кастомное поле-счётчик, значение которого можно только
уменьшать кнопкой на карточке задачи. История списаний и их откат — через
обычные комментарии к задаче, без отдельной таблицы декрементов.

**Статус: скетч.** Это рабочий пример, собранный по мотивам обсуждения
архитектуры, а не готовый к продакшену плагин — перед реальным
использованием нужно прогнать на настоящем Redmine 6.x, добавить тесты и
проверить точные названия permission-чекбоксов в вашей версии.

## Идея

- Поле — самое обычное кастомное поле Redmine (`int`), без регистрации
  своего `field_format`. Если плагин отключить, поле просто становится
  обычным целочисленным полем с последним посчитанным значением — ничего
  не ломается.
- Значение поля **всегда производное**: оно равно сумме чисел из всех
  комментариев к задаче, помеченных особым ключевым словом (токеном),
  включая самую первую запись — «сколько получили изначально». Отдельного
  поля под «исходное количество» нет: начальное число, которое
  пользователь вписывает при создании задачи, автоматически превращается
  в первый такой комментарий, и дальше поле никогда не принимает прямой
  ввод — любая попытка отредактировать его руками перезаписывается при
  следующем пересчёте.
- Конфигурация (ключевое слово для парсинга и опциональный статус, в
  который переводится задача при обнулении счётчика) хранится не в
  отдельной таблице плагина, а прямо в `description` самого кастомного
  поля — это позволяет ей путешествовать вместе с полем и оставляет нулевой
  след в схеме БД.
- Права на списание не заводятся отдельным permission — используются
  штатные права Redmine на добавление/удаление заметок (`add_issue_notes`,
  `delete_issue_notes` / `delete_own_issue_notes`). Удаление комментария —
  штатный способ откатить ошибочное списание, пересчёт срабатывает
  автоматически.
- При достижении нуля (или ухода в минус — такое может произойти только
  в обход кнопки, через прямую правку комментария) кнопка декремента
  перестаёт быть доступна; отрицательное значение не прячется, а
  показывается как есть — это сигнал, что кто-то поправил историю в обход
  штатного пути.

Более подробное обсуждение всех развилок — в issues/PR этого репозитория
по мере добавления кода.
